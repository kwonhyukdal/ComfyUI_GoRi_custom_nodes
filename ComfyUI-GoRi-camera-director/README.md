# 🎥 (GoRi) Camera Director Skills

> 🌐 [English version](README.en.md)
>
> ☕ 도움이 됐다면 커피 한 잔: [PayPal로 후원하기](https://paypal.me/GoRi57788)

주제 한 줄(한글 가능)과 참조 이미지를 넣으면 **샷·렌즈·앵글·구도·조명·색보정·무빙**이
같이 붙은 영문 프롬프트를 만들어 주는 노드입니다. 만들어진 프롬프트는 **어떤 이미지
모델에서도** 쓸 수 있습니다 — `clip` 에 그 모델의 CLIP을 연결하면 그대로 넣을 수
있고, 문자열만 복사해 KREA 2나 MiniMax H3 같은 다른 도구에도 쓸 수 있습니다.

- **API 키 없이 바로 동작합니다.** 기본 모드(규칙)는 한/영 키워드 사전으로 카메라를
  고르므로 완전 오프라인입니다.
- **AI 판단은 선택 사항입니다.** 키를 넣거나 로컬 LLM을 붙이면 장면 해석까지 맡깁니다.
- **참조 이미지는 최대 10장**이며, 어느 칸에 무엇을 넣어도 됩니다. 사람이 있는
  칸은 픽셀로 찾아 주 피사체로 삼습니다.

```
노드 이름   (GoRi) Camera Director Skills
메뉴 위치   HF Skills / Camera
```

## 빠른 시작 (3단계)

1. `topic` 칸에 장면을 한 줄 적습니다. **한글도 됩니다.** 다른 노드의 **텍스트
   박스(STRING)를 `topic` 에 연결**해도 됩니다 — 카메라 노드가 `topic` 으로
   들어오는 **포즈·동작 등 데이터를 자동으로 분류해 적용**합니다.
2. 최종 모델의 CLIP을 `clip` 칸에 연결합니다.
3. `positive_out` 을 KSampler의 `positive`, `negative_out` 을 `negative` 에 연결하고
   실행합니다.

프리셋을 하나 고르면 카메라 10칸이 자동으로 채워집니다. 참조 사진이 있으면
`image_1` 부터 연결하세요. 아래 절들이 이 과정을 하나씩 풀어 설명합니다.

> 처음이라면 노드와 함께 들어 있는 **[세팅 가이드](SETTING_GUIDE.md)** 도 보세요.
> 권장 값(한 줄 요약), 증상별 조절 표, 자주 하는 실수가 한 장에 정리돼 있습니다.

## 1. 설치

1. `ComfyUI-GoRi-camera-director` 폴더를 `ComfyUI/custom_nodes/` 안에 복사합니다.
2. ComfyUI를 재시작합니다.
3. 노드 추가 메뉴에서 **HF Skills / Camera** → **(GoRi) Camera Director Skills** 를 고릅니다.

프롬프트 생성은 외부 pip 패키지를 따로 설치할 필요가 없습니다. ComfyUI에 이미
있는 `torch`·`numpy`·`PIL`만 사용합니다.

> **참조 자동 분석은 선택 기능입니다 (5-5절).** `image_1`~`image_10` 의 역할을
> 픽셀로 판정하는 이 기능만 `mediapipe` 를 씁니다. `mediapipe` 가 없으면 분석만
> 조용히 꺼지고 프롬프트 생성은 그대로 동작합니다. 필요하면 ComfyUI 파이썬으로
> `python -m pip install mediapipe` 를 한 번 실행합니다.
>
> 포즈 판정에는 포즈 모델(`pose_landmarker_lite.task`)도 필요합니다. 이 파일은
> 이 폴더에 함께 들어 있어 따로 받을 필요가 없습니다. 다른 모델을 쓰려면
> `GORI_POSE_MODEL` 환경변수에 `.task` 파일의 전체 경로를 넣습니다.
> 사물 판정에 쓰는 모델(`efficientdet_lite0.tflite`)도 이 폴더에 함께 들어
> 있습니다.

## 2. 첫 배선

```text
텍스트 상자 (STRING) ─────────────────────→ topic        (선택)
최종 모델의 CLIP ─────────────────────────→ clip
프롬프트 재작성 노드 ────── positive_prompt → prompt_in
참조 사진 ────────────────────────────────→ image_1
포즈 맵 (DWPreprocessor 몸만) ────────────→ pose_image   (선택)
최종 모델의 VAE ──────────────────────────→ vae          (선택)
고해상도 latent 노드 ─────────────────────→ latent_image (선택)
기존 negative conditioning ───────────────→ negative     (선택)

(GoRi) Camera Director Skills
  ├─ positive_out ────────→ KSampler.positive
  ├─ negative_out ────────→ KSampler.negative
  ├─ prompt_out ──────────→ Show Text (확인용)
  ├─ image_out ───────────→ I2V 시작 프레임 / 업스케일 (선택)
  └─ reference_latent_out → KSampler.latent_image / VAE Decode (선택)
```

가장 짧은 경로는 **topic에 장면을 한 줄 적고, `clip`만 연결하는 것**입니다.
`prompt_in`을 연결하지 않아도 노드가 topic으로 프롬프트를 직접 만듭니다.

> **`topic` 은 직접 적지 않고 텍스트 박스로 채울 수도 있습니다.** `topic` 칸을
> 입력으로 바꾼 뒤(칸을 우클릭) 다른 노드의 **텍스트 상자(STRING)** 출력을 이으면
> 됩니다. 카메라 노드는 `topic` 으로 들어오는 **포즈·동작 등 데이터를 자동으로
> 분류해 적용**합니다 — 직접 적은 글과 똑같이 처리합니다.

> **clip에는 최종 모델의 CLIP을 연결하세요.** 어떤 모델이든 **그 모델의** CLIP을
> 씁니다. 서로 다른 모델의 CLIP을 섞으면 얼굴과 피부가 깨질 수 있습니다.

> **프롬프트 재작성기의 CLIP을 여기 `clip`에 연결하지 마세요.**
> 재작성기에서는 **문자열**(`positive_prompt`)을 `prompt_in`에 넣고,
> `clip`에는 최종 이미지 모델의 CLIP을 연결합니다.

## 3. 출력 5종

| 출력 | 타입 | 연결할 곳 | 설명 |
|---|---|---|---|
| `positive_out` | CONDITIONING | `KSampler.positive` | 최종 프롬프트를 한 번 인코딩한 결과 |
| `negative_out` | CONDITIONING | `KSampler.negative` | 기존 negative가 있으면 유지하고 실패 방지 문구만 추가 |
| `prompt_out` | STRING | Show Text, 다른 프롬프트 노드 | 실제로 쓰인 영문 문자열. 확인용이며 KREA 2 등에 그대로 붙여넣을 수 있음 |
| `image_out` | IMAGE | I2V 시작 프레임, 업스케일 | 주 참조 이미지를 그대로 통과. 이미지를 연결하지 않으면 비어 있음 |
| `reference_latent_out` | LATENT | KSampler, VAE Decode | 주 참조 이미지의 latent. `latent_image`를 연결하면 **그 노드가 정한 가로·세로 그대로** 나가고, 연결하지 않으면 참조 이미지의 비율을 따릅니다. `vae`를 연결해야 채워짐 |

> **시트 이미지는 `image_out`·`reference_latent_out`에서도 빠집니다.** 캐릭터
> 시트가 주 참조로 잡혀도 시트 대신 시트가 아닌 다른 참조가 나갑니다. 시트가
> 그대로 나가면 뒤 노드(I2V·업스케일)가 여러 칸 시트를 그리기 때문입니다.
> 시트 말고 연결된 참조가 없으면 두 출력은 비어 있습니다.

> **`reference_latent_out`은 샘플러의 시작 latent로 그대로 쓸 수 있습니다.**
> `latent_image`에 빈 latent(Empty Latent Image, Deno Resolution 등)를 연결하면
> 그 노드가 정한 **가로·세로 그대로** 나갑니다. 1:1, 4:5, 3:4, 2:3, 16:9, 9:16,
> 16:10, 21:9 등 어떤 비율이든 같습니다 — 샘플러가 만드는 이미지 크기는 시작
> latent의 크기가 정하기 때문입니다. `latent_image`를 연결하지 않으면 종전처럼
> 참조 이미지의 비율을 따릅니다. 다만 `denoise=1.0` 이면 시작 latent의 **모양이
> 곧 시드**라, 비율을 바꾸면 같은 시드에서도 결과가 달라집니다(4-8).

> `positive` 단자는 예전 워크플로와의 호환용으로 남아 있습니다. 새 경로에서는
> 쓰지 않으며, 연결해도 무시됩니다. 프롬프트는 이 노드가 직접 만듭니다.

## 4. 화면 위젯 사용법

위에서부터 순서대로 **주제 → 프리셋 → 자동화 → 카메라 10칸 → AI LLM 설정** 입니다.
프리셋 줄과 기능 팝업 창의 오른쪽 위에는 값을 되돌리는 **↻ 새로고침 버튼**도
있습니다(4-9). 프리셋 줄의 ↻ **바로 아래 칸**(자동화 줄)에는 저장 창을 여는
**저장 아이콘**도 있습니다(4-10).

### 4-1. topic — 장면 한 줄

하고 싶은 장면을 그대로 적습니다. **한글도 됩니다.**

```
비 오는 골목에서 검은 코트를 입은 여성이 뒤를 돌아본다
```

- **텍스트 박스(다른 노드의 STRING)를 `topic` 에 연결해도 됩니다.** `topic` 칸을
  입력으로 바꾸고(칸을 우클릭) 텍스트 박스의 출력을 이으면 됩니다. 카메라 노드는
  `topic` 으로 들어오는 **포즈·동작 등 데이터를 자동으로 분류해 적용**합니다.
- `prompt_in`에 선을 연결하면 **topic 칸 대신** 그 문자열을 씁니다.
  선을 끊으면 다시 topic 칸으로 돌아옵니다. 다만 topic 칸에 적은 글도 **버려지지
  않습니다** — 슬롯 지목(`2번은 포즈`)·가림 지시(`가려줘`)·매크로 같은 안전장치
  판정에는 함께 반영됩니다.
- topic에 샷을 직접 적으면(`전신`, `close-up shot` 등) 드롭다운 기본값보다
  **적어 둔 표현을 우선**합니다.
- 조명·무빙 키워드도 읽습니다. `네온`, `노을`, `스튜디오`, `실루엣`, `심야`,
  `화사한` 같은 단어가 조명을 정하고, `천천히 다가가며` 같은 표현이 무빙을 정합니다.
- **한 문장이든 태그 나열이든 모두 읽습니다.** `1girl, red dress, neon, night street`
  처럼 쉼표로 늘어놓은 태그형 프롬프트도, "비 오는 골목에 선 여성" 같은 문장형도
  똑같이 해석합니다. 참조 이미지의 역할(포즈·의상 등)을 판단할 때는 태그 속
  장식용 단어를 걸러 내 오해를 줄입니다.
- 카메라와 무관한 대사·설명을 길게 넣어도 됩니다. 카메라 조항만 뒤에 붙습니다.
- **어떻게 써야 잘 지켜지는지는 4-7 을 보세요.** 사람·팔 위치·옷 이름을 적는 것이
  특히 중요합니다.

### 4-2. preset — 한 번에 분위기 정하기

프리셋을 고르면 **아래 카메라 10칸이 그 프리셋 값으로 자동으로 채워집니다.**
프리셋을 바꿔도 각 프리셋에서 마지막으로 쓰던 상태는 사라지지 않습니다 —
프리셋별로 기억됩니다(4-4 끝 안내). 직접 바꾼 값을 프리셋 기본값으로 되돌리려면
프리셋 줄의 **↻ 버튼**을 누르세요(4-9).

| 프리셋 | 느낌 |
|---|---|
| `자동 (auto)` | 장면에 맞춰 규칙 또는 AI가 고름 (기본) |
| `시네마틱 인물 (cinematic portrait)` | 인물 사진의 표준 조합 — 85mm·중근접·램브란트 조명·시네마틱 색보정 |
| `제품 히어로 (product hero)` | 제품을 선명하게 보여주는 조합 — 100mm 매크로·중앙 대칭·3점 스튜디오 |
| `CF 버티컬 (vertical ad)` | 세로 광고용 조합 — 중근접·중앙 대칭·비비드 색보정 |
| `다큐 핸드헬드 (doc handheld)` | 현장감 있는 조합 — 35mm·흐린 부드러움·프리미엄 색보정 |
| `드라마틱 롱샷 (dramatic long shot)` | 원경·로우앵글·로우키·강한 대비 |

> **모든 프리셋은 서로 다른 값으로 구성되어 있습니다.** 골라도 화면이 바뀝니다.
> 프리셋 값을 직접 바꾸려면 아래 카메라 10칸에서 고르세요.
>
> **프리셋은 무빙(`motion`)을 담지 않습니다.** 무빙은 영상 파이프라인에서만
> 쓰이는 값이라, 프리셋을 고르면 `motion`·`motion2`는 `없음 (none)`으로
> 남습니다. 움직임을 연출하려면 `motion` 칸에서 직접 고르세요.

### 4-3. automation — 누가 카메라를 고르는가

| 모드 | 동작 | 언제 |
|---|---|---|
| `규칙 (auto)` **(기본)** | 한/영 키워드 사전으로 고름. 오프라인·무료 | 키 없이 바로 쓸 때 |
| `AI 판단 (llm)` | LLM이 장면을 영문으로 풀어 쓰고 카메라도 고름 | 키가 있고 더 똑똑한 결과를 원할 때 |

`AI 판단 (llm)`은 키가 없거나 네트워크가 끊기면 **자동으로 규칙으로 돌아갑니다.**
실행이 실패하는 일은 없습니다.

### 4-4. 카메라 드롭다운 10칸

| 위젯 | 정하는 것 | 선택지 |
|---|---|---|
| `shot` | 화면에 인물이 얼마나 크게 잡히는가 | 7종 (극접~극원경) |
| `lens` | 렌즈 화각과 배경 압축 | 8종 (14mm~200mm, 매크로) |
| `angle` | 카메라 높이와 방향 | 13종 (수평·로우앵글·POV·탑다운 등) |
| `composition` | 화면 배치 | 8종 (삼분할·중앙 대칭·리딩라인 등) |
| `lighting` | 빛의 성질 | 10종 (창가빛·골든아워·램브란트·로우키 등) |
| `grade` | 색 보정 | 8종 (시네마틱 필름·비비드·느와르 등) |
| `motion` | 카메라 움직임 (영상 전용) | 22종 (푸시인·팬·오빗·핸드헬드 등) |
| `speed` | 움직임 속도 | 느림 / 보통 / 빠름 |
| `amplitude` | 움직임의 세기 | 약간 / 보통 / 강하게 |
| `motion2` | 두 번째 움직임 (영상 전용) | `motion`과 같은 22종 |

> 화면에서 `motion`·`motion2`는 **`motion (only video)`** 처럼 이름 뒤에
> `(only video)` 가 붙어 표시됩니다. 무빙은 영상 파이프라인에서만 반영되고
> 정지 이미지에서는 무시되기 때문입니다.

**다중 선택** — 드롭다운을 클릭하면 항목 목록이 뜨고, 항목마다 켜고 끄는
스위치가 있습니다. 여러 개를 켜면 그 조항이 **모두** 프롬프트에 들어갑니다.
켠 개수는 위젯 칸에 `수동 (2개)`처럼 표시되고, 캔버스 빈 곳을 클릭하면 닫힙니다.
`자동 (auto)`는 목록에 없으며, 헤더가 그 자리를 대신합니다.

- `speed`와 `amplitude`는 움직임에 붙는 수식이라 **첫 번째 값만** 쓰입니다.
- 한 항목이라도 알 수 없는 값이 섞이면 그 칸은 통째로 `자동`으로 봅니다.
- `motion`과 `motion2`를 함께 고르면 두 움직임이 합쳐집니다(예: 푸시인 + 팬).
  `없음 (none)`은 "움직임 조항을 넣지 않음", `정지 (static)`은 "카메라를 고정"입니다.

**프리셋 위에 더하고 빼기**

프리셋을 고르면 열 칸이 그 값으로 채워집니다. 이때 프리셋은 **칸별 기준값**이고,
드롭다운은 그 위에 얹는 가감입니다.

| 하고 싶은 것 | 하는 법 | 결과 |
|---|---|---|
| 프리셋 그대로 | 아무것도 건드리지 않음 | 열 칸 모두 프리셋 값 |
| 항목 추가 | 그 칸에서 항목을 하나 더 켬 | 프리셋 값 **+ 추가분**이 함께 들어감 |
| 항목 교체 | 기존 항목을 끄고 새 항목을 켬 | 그 칸만 새 값 |
| 항목 제거 | 그 칸을 `자동 (auto)`로 되돌림 | 그 칸만 프리셋에서 빠지고 규칙/AI가 채움 |

예를 들어 `드라마틱 롱샷`(로우키)에서 조명에 `네온`을 더하면 **로우키 + 네온**이
둘 다 들어갑니다. 로우키가 싫으면 로우키를 끄고 네온만 켜 두세요.

> 프리셋을 통째로 끄려면 `preset` 칸을 `자동 (auto)`로 바꾸세요. 열 칸을 모두
> 비우는 방식은 쓰지 않습니다 — 위젯을 채우지 않고 API로 큐에 넣는 정상 경로와
> 구분할 수 없기 때문입니다(그 경우 프리셋 전체가 적용됩니다).

**체크는 사라지지 않습니다 — 프리셋별로 기억**

프리셋을 바꿔도 각 프리셋에서 켜 둔 항목은 사라지지 않습니다. 예를 들어
`자동 (auto)`에서 조명에 항목을 더하고 `시네마틱 인물`로 갔다가 다시 `자동 (auto)`
로 돌아오면, 전에 켜 둔 항목이 그대로 돌아옵니다. 프리셋마다 마지막 상태를
따로 기억하기 때문입니다. 새로고침·ComfyUI 재시작 뒤에는 워크플로에 저장된
상태가 복원되고, 그 상태에서 기억이 다시 시작됩니다.

손으로 바꾼 값을 되돌리는 버튼은 따로 있습니다 — 프리셋 줄과 기능 팝업 창의
**↻ 새로고침 버튼**입니다. 위치와 동작은 **4-9** 에 정리해 두었습니다.

### 4-5. AI LLM 설정 (접혀 있음)

새로 꺼낸 노드는 **`AI LLM 설정`** 이라는 접힌 줄로 시작합니다. 줄을 클릭하면
아래 5칸이 펼쳐집니다. 접은 상태는 워크플로에 저장되므로 다음에 열어도 그대로입니다.

| 칸 | 설명 |
|---|---|
| `provider` | OpenAI · Anthropic · Gemini · OpenRouter · Groq · DeepSeek · Mistral · Ollama · LM Studio · Custom (OpenAI 호환) |
| `model` | 모델 이름. 비우면 provider 기본값 |
| `api_key` | 키. 비워도 `.env` 파일이나 환경변수에서 찾습니다 |
| `custom_base_url` | `Custom (OpenAI 호환)` 일 때만 쓰는 주소 |
| `vision_detail` | 이미지를 LLM에 보낼 때의 크기: `선명 (768)` / `균형 (512)` / `절약 (384)` |

표에 없는 칸이 하나 더 있습니다 — `llm_hint` 입니다. LLM에 보낼 짧은 지시를 넣는
칸인데 **화면에는 나오지 않습니다**(API·스크립트 전용). `AI 판단 (llm)` 으로 실행할
때만 적용되고, `규칙 (auto)` 에서는 무시합니다.

`AI 판단 (llm)`으로 실행하면 `model` 칸에 **초록불이 점멸**합니다. 로컬 LLM은
수십 초 걸릴 수 있어 진행 중인지 바로 알 수 있습니다. 판정이 끝나면 잠시 초록불이
유지되고, 실패해서 규칙으로 돌아가면 **빨간불**이 켜집니다.

### 4-6. 출발 점검 (선택)

노드 아래 `pf_steps` · `pf_cfg` · `pf_denoise`에 **KSampler에 적은 값을 그대로**
옮겨 적으면, 실행 전에 위험한 조합을 콘솔에 경고합니다. 0이면 검사하지 않습니다.

| 칸 | 적는 값 |
|---|---|
| `pf_steps` | KSampler의 `steps` |
| `pf_cfg` | KSampler의 `cfg` |
| `pf_denoise` | KSampler의 `denoise` |

- 극접·근접인데 latent가 너무 작으면 얼굴이 뭉개질 수 있다고 알려 줍니다.
- steps·cfg가 일반 범위를 크게 벗어나면 알려 줍니다.
- denoise가 0.9를 넘으면 원본에서 멀어진다고 알려 줍니다.

> 이 칸은 **경고만** 합니다. 값을 막거나 바꾸지 않습니다.

### 4-7. 프롬프트 작성 가이드 — 다섯 가지

**적어 준 것만 지킵니다.** 적지 않은 것은 모델이 매번 다르게 채웁니다.

**① 사람을 부르는 말을 넣으세요**

```
여성은 청바지를 입고 실내 의자에 앉아 있다      (O)
청바지를 입고 실내 의자에 앉아 있다            (X — 사람을 부르는 말이 없음)
```

노드는 문장에서 사람을 찾아 얼굴·손가락·팔다리 안전장치를 붙입니다. 사람을
부르는 말이 없으면 그 문구들이 **하나도 붙지 않습니다.**

`여성`·`여자`·`사람`·`모델`(한글)은 번역을 거쳐도 사람을 뜻하는 말로 남아 안전합니다.
번역기를 쓸 때 특히 주의하세요 — 같은 뜻이라도 번역이 `He` 로 가면 안전장치가
조용히 빠집니다.

**② 팔과 손이 어디 있는지 적으세요**

```
여성이 의자에 앉아 양손을 무릎에 올려놓고 정면을 본다    (O)
여성이 의자에 앉아 정면을 본다                        (X — 팔은 어디에도 없음)
```

참조 사진의 팔이 새 자세에 그대로 옮겨지지 않을 때(예: 서서 무엇을 잡고 있는 팔 →
앉은 자세) 자리를 적어 주지 않으면 **팔 하나가 사라질 수 있습니다.**

**③ 옷 이름을 적으세요**

옷을 이름으로 적지 않으면 **참조 이미지가 유일한 기준**이고, 자세를 바꾸면 그 부위를
다시 그리므로 결과가 달라집니다. `긴 청바지` 처럼 이름을 적어 두면 그대로 유지됩니다.

**④ 신발은 형용사와 명사를 붙여 쓰세요**

`앞이 막힌 단화`(O). `앞이 막힌 반바지`처럼 신발을 뜻하는 형용사가 다른 옷에 붙으면
콘솔에 경고 한 줄이 남습니다. 경고는 실행을 막지 않고 알려만 줍니다.

**⑤ 시드는 고정하고 한 번에 하나만 바꾸세요**

제약이 많아지면 모델은 그중 **일부만** 지킵니다. 어느 것이 빠지는지는 매번
달라지므로, 비교할 때는 **시드를 고정**하고 문장만 고치세요. 시드를 바꿔 가며 좋은
한 장을 고르는 것은 재현이 되지 않습니다.

> 안전장치는 **확률을 올릴 뿐 보장하지 않습니다.** 적은 대로 나오지 않으면 위 다섯
> 가지를 하나씩 늘려 보세요. 무엇이 붙었는지는 콘솔 로그와 `prompt_out` 에서 볼 수
> 있습니다.

### 4-8. 참조 이미지 해상도 — 입력 해상도를 그대로 따릅니다

참조 이미지는 **`latent_image` 에 연결한 해상도 노드의 픽셀 수를 그대로** 따라
조건화에 들어갑니다. 노드 맨 아래(포즈 단자 다음)의 숫자 칸 `reference_max_mp` 는
**화면에 보이지 않고 값도 쓰이지 않습니다** — 값의 출처가 입력이 됐기 때문입니다.
(저장된 워크플로의 위젯 값이 한 칸씩 밀리는 문제를 막기 위해 **자리만 지키는
숨김 칸**으로 남겨 둡니다.)

| 해상도 노드(입력) | 참조 조건화 |
|---|---|
| 1.0MP (예: 1344x768) | 참조도 1.0MP 급 — 세로 사진이면 752x1360 (픽셀 수가 같습니다) |
| 2.0MP | 참조도 2.0MP 급 |
| 0.5MP | 참조도 0.5MP 급 (작으면 작게) |
| 연결하지 않음 | 따를 입력이 없으므로 1MP 로 맞춥니다 |

- **왜 없앴나**: 종전에는 그 칸으로 참조를 입력보다 크게(입력 1MP 인데 참조 2MP)
  인코딩할 수 있었습니다. 생성에 쓰이지 않는 해상도라 정보가 늘지 않고, 참조와
  결과의 픽셀 격자가 어긋납니다. 입력에 맞춰 주는 것이 맞습니다.
- 참조 **사진의 종횡비는 그대로** 둡니다 — 자르거나 여백을 넣지 않습니다. 픽셀 수
  (격자 칸 수)만 입력과 같아집니다.
- **참조 사진의 모양을 캔버스 모양과 똑같이 맞추고 싶다면, 사진을 그 모양으로
  준비해서 넣으세요.** 노드가 사진을 잘라내거나(크롭) 여백을 채워(레터박스) 모양을
  맞추지는 않습니다. 크롭은 옷과 얼굴을 바꾸고, 여백(레터박스)은 이득이 없으며,
  늘리기는 체형과 얼굴을 왜곡합니다. 사용자가 미리 준비한 사진은 위 규칙이 그 모양
  그대로 처리합니다.
- **생성 이미지의 종횡비와 크기는 해상도 노드가 정합니다.** 1:1, 16:9, 9:16, 21:9
  등 어떤 비율이든 그대로 나갑니다(5번 출력이 그 크기 그대로 나갑니다).
- **대가:** 샘플러의 시작 latent 로 `reference_latent_out` 을 쓰면
  시작 latent 의 **모양이 곧 시드**가 됩니다(`denoise=1.0`). 그래서 비율 위젯을
  바꾸면 같은 시드라도 그림이 달라집니다. 이것은 결함이 아니라 비율을 바꾸는 행동의
  필연적 결과입니다 — 비율이 달라지면 캔버스가 달라지고, 캔버스가 달라지면 노이즈
  텐서가 달라지기 때문입니다. 같은 시드로 같은 그림을 얻으려면 **비율을 바꾸지
  마세요.**
- 생성 크기를 키우면 참조도 같이 커집니다. **스텝당 시간도 참조 크기를 따릅니다** —
  참조를 2배로 하면 시간이 약 3.4배, 절반으로 하면 약 0.7배가 됩니다.
  8GB 카드라면 해상도 노드를 1MP 근처로 두세요.

### 4-9. ↻ 새로고침 — 프리셋 기본값으로 되돌리기

프리셋으로 채운 뒤 몇 칸을 손으로 바꿨을 때, **처음 상태로 되돌리는 버튼**입니다.
둘 다 **브라우저 새로고침 모양(↻)** 이고, 평소에는 화살표만 보이며 마우스를
올리면 배경이 나타납니다.

| 버튼 | 위치 | 누르면 |
|---|---|---|
| 프리셋 줄의 ↻ | 프리셋 줄 **오른쪽 끝에서 한 칸 안쪽** | 카메라 10칸 **전체**를 지금 고른 프리셋의 기본값으로 |
| 팝업 창의 ↻ | 기능 팝업 창(shot·lens 등을 눌렀을 때 열리는 창) **오른쪽 위** | **그 창의 항목만** 그 프리셋의 기본값으로 |

- 기준은 **지금 고른 프리셋의 기본값**입니다. 프리셋이 정해 준 값은 그대로 남고
  사용자가 바꾼 부분만 돌아갑니다. 프리셋이 정해 주지 않은 칸은 `자동 (auto)` 가
  됩니다.
- 팝업 창의 ↻ 는 **그 창만** 되돌립니다 — 다른 창과 프리셋 설정은 그대로입니다.
- 되돌린 결과는 그 프리셋의 기억에도 반영됩니다. 다음에 그 프리셋으로 돌아오면
  되돌린 상태가 그대로 나옵니다(4-4 의 "체크는 사라지지 않습니다" 참조).

### 4-10. 저장 — 저장 창(`user preset`)

프리셋 줄의 ↻ **바로 아래 칸**(자동화 줄의 오른쪽 끝에서 한 칸 안쪽)에 **저장
아이콘**이 있습니다. 모양은 **플로피 디스크**이고, 크기와 마우스 호버 동작은
↻ 와 같습니다 — 평소에는 아이콘만 보이고 마우스를 올리면 배경이 나타납니다.

누르면 **저장 창이 오른쪽에 열립니다**. 이 창은 다른 설정 창(shot·lens 등을
눌렀을 때 열리는 창)과 똑같이 동작합니다.

| 창의 자리 | 무엇인가 |
|---|---|
| 왼쪽 위 | `user preset` — 이 창의 이름 |
| 오른쪽 위 | **저장 버튼** — 누르면 지금 카메라 값을 그 이름으로 저장합니다 |
| 헤더 아래 | **이름 입력칸** — 안에 `preset name` 안내 글씨가 흐리게 보입니다 |
| 가운데 | 저장해 둔 프리셋 목록 — 항목마다 체크박스 줄로 나옵니다 |
| 각 줄 오른쪽 끝 | **휴지통 아이콘** — 누르면 지울지 묻고, 확인하면 그 프리셋을 지웁니다 |

**이름을 넣고 저장 버튼을 누르면** 지금 카메라 값 10칸(shot·lens·angle·
composition·lighting·grade·motion·motion2·speed·amplitude)이 그 이름으로
저장됩니다. 저장된 이름은 창 가운데 목록에 바로 나타나고 입력칸은 비워집니다.

- **저장 버튼은 사용자 프리셋만 저장합니다.** 워크플로 파일 저장은 예전처럼
  키보드 `Ctrl+S` 로 합니다.
- 같은 이름으로 다시 저장하면 **덮어씁니다** — 값을 바꾸고 같은 이름으로 저장하면
  그 프리셋이 새 값으로 갱신됩니다.
- 이름을 넣지 않고 누르면 저장하지 않고 "이름을 먼저 입력하세요" 라고 알려 줍니다.
- 저장한 파일은 설치한 카메라 노드 폴더 안 **`user_presets`** 폴더에 이름별
  JSON 파일로 남습니다(예: `시네마틱 인물.json`). 그 폴더의 파일을 지우면 그
  프리셋이 지워집니다.
- **목록 줄 오른쪽 끝의 휴지통을 누르면** 그 프리셋을 지울지 **먼저 묻습니다.**
  확인을 누르면 지워지고, 취소하면 아무 일도 일어나지 않습니다.
- 지우면 **`user_presets` 폴더의 파일도 함께 사라집니다.** 화면 목록과 폴더가
  항상 같은 상태로 남습니다 — 화면에서 지우고 폴더에 파일이 남는 일이 없습니다.
- 목록의 체크박스를 **체크하면 그 프리셋의 이름이 아래 `user preset` 칸에
  올라갑니다**(프리셋 목록을 열면 보입니다). 여러 개를 체크하면 그 이름들이 모두
  쌓입니다. **체크 자체는 카메라 값도, 노드 맨 위 `preset` 칸 이름도 바꾸지
  않습니다** — 이름을 목록에 올려 두는 일만 합니다.
- **값은 아래 `user preset` 목록에서 이름을 눌렀을 때 들어갑니다** — 그때 프리셋
  값 10칸이 카메라 노드에 실제로 들어가고, 노드 맨 위 `preset` 칸 이름도 그
  프리셋으로 바뀝니다.
- **체크를 풀면 카메라가 자동으로 돌아갑니다.** 노드 맨 위 `preset` 칸이 `자동
  (auto)` 가 되고, 값 10칸도 모두 `자동 (auto)` 로 바뀝니다.
  (되돌리기는 그 프리셋 줄의 ↻ 도 있습니다.)
- **체크한 것은 워크플로에 함께 저장됩니다.** 노드를 저장(워크플로 저장)해 두면
  브라우저를 새로고침하거나 ComfyUI 를 다시 실행해도 체크가 그대로 남아 있습니다 —
  다시 열었을 때 다시 체크하지 않아도 됩니다.
- 저장된 프리셋이 하나도 없으면 창 가운데에 `아직 설정 항목이 없습니다` 한 줄이
  보입니다.
- 다른 설정 창과 같이, **창 밖을 클릭하면 닫히고** 캔버스를 움직이거나 확대하면
  창도 노드와 함께 따라갑니다.
- 아이콘이 안 보이면 브라우저를 **Ctrl+F5**(강력 새로고침)로 한 번 새로 고치세요.
  실행 중인 페이지는 예전 화면 파일을 기억하고 있을 수 있습니다.

**프리셋 목록 아래에도 `user preset` 이라는 이름표가 붙습니다.** 프리셋 줄(`preset`)
을 누르면 펼쳐지는 목록(맨 위에 `Filter list` 입력칸, 그 아래 `자동 (auto)`·
`시네마틱 인물` …) **바로 아래**에 `user preset` 칸이 이어서 나타납니다. 그 칸에는
**저장 창에서 체크해 둔 프리셋의 이름**이 보이고, 체크한 것이 없으면
`아직 설정 항목이 없습니다` 한 줄이 보입니다.

**그 이름을 누르면 그 프리셋이 골라집니다** — 프리셋 값 10칸이 카메라 노드에
들어가고, 노드 맨 위 `preset` 칸 이름도 그 프리셋으로 바뀌고(예: `자동 (auto)` →
`내 프리셋`), 드롭다운이 닫힙니다. 값은 노드의 `shot`·`lens`·`angle`·
`composition` … 칸에 그대로 보입니다. 이 칸에서 저장·삭제는 할 수 없습니다 — 그
둘은 위에서 설명한 저장 아이콘 창에서 합니다.

> **주의 — 노드를 갱신하면 프리셋이 사라질 수 있습니다.** `user_presets` 폴더는
> 노드 폴더 안에 있으므로, ComfyUI Manager 로 노드를 업데이트하면 폴더가 함께
> 지워질 수 있습니다. 남기고 싶은 프리셋이 있으면 갱신 전에 `user_presets` 폴더를
> 다른 곳에 복사해 두세요.

## 5. 참조 이미지 (`image_1` ~ `image_10`)

### 5-1. 단자와 역할

단자는 처음에 `image_1` 하나만 보입니다. 선을 연결할 때마다 **다음 칸이 하나씩**
나타납니다. 화면에 안 보이는 것일 뿐 저장된 워크플로의 연결은 그대로입니다.

| 슬롯 | 역할 |
|---|---|
| `image_1` ~ `image_10` | 어느 칸이든 **주 피사체(얼굴·체형·의상 기준)** 가 될 수 있습니다. 역할은 번호가 아니라 내용으로 정해집니다 |

- 사람이 있는 칸은 픽셀로 찾아 주 피사체 후보로 삼습니다(5-5).
- 주 피사체가 아닌 칸은 topic에 역할을 적어야 그 역할로 씁니다. 적지 않으면
  얼굴·머리·피부·의상·신원을 **따라 하지 않습니다**(복제 방지).

#### 번호로 역할 적기 — 콜론(`:`)이 기준입니다

토픽에서 번호로 역할을 적는 표기입니다. **`N번:` 처럼 콜론을 붙이면 그 번호가 그
역할로 정해집니다.** 콜론은 "이 번호는 이 역할" 이라는 **선언 표지**입니다.

**쓰는 법 네 가지** — 번호 + `번` + 콜론 + 역할 낱말.

```
1번: 한국 여성
2번: 의자
3번: 하이 힐
4번: 배경
연출: <장면 문장>
```

1. 번호 뒤에 `번`(또는 `번째`)을 쓰고 **콜론(`:`)** 을 붙입니다. `번` 은 필수입니다
   — `16:9` 같은 **비율 표기**가 콜론 선언으로 읽히지 않게 하는 조건입니다.
2. 콜론 **뒤**에 역할 낱말을 씁니다. **띄어쓰기는 자유**입니다
   (`3번: 하이힐` = `3번: 하이 힐`).
3. 조사는 붙여도 됩니다(`2번: 의자를` → 2번 = 사물).
4. 한 줄에 하나씩, 또는 `/` 로 나눠 적습니다.

| 적는 법 | 읽는 결과 |
|---|---|
| `2번: 의자` | 2번 = 사물 |
| `3번: 하이 힐` · `3번: 하이힐` | 3번 = 의상 (띄어쓰기는 자유) |
| `4번: 배경` | 4번 = 배경 |
| `1번: 한국 여성` | 1번 = 인물 |
| `둘째: 의자` · `두 번째: 의자` | 2번 = 사물 (한글 수사도 번호로 읽습니다) |
| `피사체: 1번 이미지` | 1번 = 주 피사체 |
| `이미지 2의 핸드백` · `2번 이미지 의자` | 종전 표기 그대로 (사물) |
| `2번 앉은 자세` | 2번 = 포즈 |
| `연출: <문장>` | 이 줄 뒤 문장만 장면이 됩니다 (라벨 줄은 장면이 아닙니다) |

**콜론 없이도 읽는 표기** — 의상·배경·포즈와 종전 이미지 표기는 그대로 됩니다:
`3번 하이힐` · `4번 배경` · `2번 앉은 자세` · `2번 이미지 의자` ·
`이미지 2의 핸드백`.

**일부러 열지 않은 표기** — 아래는 읽지 않습니다.

| 적는 법 | 왜 안 읽나 |
|---|---|
| `2번 의자` (콜론 없음) | **선언과 문장을 가릴 근거가 없습니다.** `2번 옷을 입혀`(사람) 같은 착용 문장이 의상 표기로 새어 듭니다. 콜론을 붙여 주세요 |
| `1번: 앉아` · `2번: 신겨` | 선언 자리에 온 **동사**는 물건 선언이 아니라 동작입니다. 포즈는 `2번 앉은 자세`처럼 자세 낱말을 쓰세요 |

**왜 콜론이 필요한가**: 콜론이 없으면 **선언**과 **문장**을 가릴 근거가 없습니다.
`2번 의자`(선언)와 `2번 의자를 밀어`(문장), `2번: 하이힐`(선언)과 `2번 하이힐을
신겨`(문장)는 글자만으로 같은 모양입니다. 문장을 선언으로 잘못 읽으면 그 사람이
결과에서 사라질 수 있습니다. 그래서 콜론이 없으면 역할로 묶지 않습니다.

**그래도 조용하지는 않습니다** — 콜론 없이 역할처럼 보이는 표기를 쓰면 노드가
콘솔에 한 줄로 알려 줍니다. **안내는 판정을 바꾸지 않습니다**(프롬프트는 그대로
나갑니다).

```
[Camera Director] 콜론 없는 역할 표기 "2번 의자" — 역할로 읽지 않습니다.
그 칸을 역할로 쓰려면 2번: 의자 처럼 콜론을 붙여 주세요 (문장의 일부였다면 그대로 두세요)
```

안내 대상은 **사물·인물** 표기뿐입니다 — 콜론 없이도 읽히는 의상·배경·포즈와
`2번 이미지 의자` 같은 표기는 안내하지 않습니다. 문장의 주어일 수도 있으므로
"역할로 쓰려면" 이라고 조건부로 말합니다. 안내는 실행 한 번에 한 줄입니다.

**낱말의 품사는 자동으로 나눕니다.** 명사·수사는 사물·의상·배경·인물 어휘에서,
동사는 상태·교체 판정에서(`신발을 신고`는 상태, `신겨`는 교체), 형용사·부사·
관형사는 수식 판정에서(`같은`은 유지, `다른`은 교체) 봅니다. **모르는 낱말은
예전과 똑같이 처리**합니다 — 자동 분류가 기존 판정을 뒤집지 않습니다.

한 번호를 여러 역할로 적으면 **포즈 > 사물 > 인물** 순으로 이깁니다.

### 5-2. 포즈 지정

topic에 **번호 + 자세**를 적으면 그 이미지는 포즈 전용이 됩니다. 1~10번 전부
가능하고 여러 개를 동시에 지정할 수 있습니다.

```
2번 이미지의 포즈를 따라
3번과 7번 이미지의 자세
2번은 포즈만
2번 앉은 자세
```

포즈로 지정한 칸은 포즈에만 쓰이고, 얼굴·의상·사물 기준에서는 빠집니다. 그래서
포즈 참조의 얼굴이나 옷이 주인물에 섞이지 않습니다.

`AI 판단 (llm)` 모드에서는 topic에 번호를 적지 않아도, LLM이 각 참조 이미지의
자세를 보고 **포즈 참조로 쓸 칸을 스스로 골라** 라벨을 붙입니다. 다만 그 판단은
픽셀로 한 번 더 확인되어, 실제로 사람이 검출된 칸에만 적용됩니다(엉뚱한 칸에
붙지 않도록).
topic에 `2번은 포즈만`처럼 **직접 적으면 항상 그 지시가 우선**합니다.

#### 포즈 맵 이미지로 지정하기 (`pose_image`)

뼈대 그림을 `pose_image` 단자에 연결하면 그 자세를 읽어 프롬프트에 보탭니다.
읽어 내는 자세는 **앉음 · 서 있음 · 눕기** 세 가지입니다.

1. `DWPreprocessor` 같은 포즈 추출 노드를 준비합니다.
2. 그 노드에서 **손·얼굴 그리기를 끄고 몸만** 그리게 합니다.
3. 결과(검은 배경에 색 뼈대)를 `pose_image`에 연결합니다.

- 포즈 맵은 참조 사진이 **아닙니다.** 참조 개수·얼굴·의상 판정에 끼어들지 않습니다.
- 손·얼굴까지 그린 맵은 점이 겹쳐 자세를 잘못 읽을 수 있습니다. 몸만 그린
  맵이 가장 정확합니다. 읽지 못하면 아무 일도 일어나지 않고 topic 묘사만으로
  동작합니다.
- topic에 자세를 함께 적어도 됩니다. 둘 다 쓰이며 서로 지우지 않습니다.
- 연결하지 않으면 예전과 똑같이 동작합니다.

#### 포즈를 바꾸면 얼굴은 다시 그려집니다

포즈를 지시하면(토픽의 `앉아`, `걷고 있다` 또는 포즈 맵) 모델이 몸을 새로
그리면서 **얼굴도 새로 그립니다.** 이때 노드가 자동으로 얼굴 고정 문구를
negative에 넣어 참조 인물 쪽으로 되돌립니다. 그래도 완전히 같아지지는 않습니다.

얼굴이 중요한 컷은 이렇게 하세요.

- **토픽에 포즈 문장을 쓰지 않습니다.** 배경·소품만 바꾸는 용도라면 토픽을
  비우는 편이 가장 안전합니다.
- **샷을 `중경 (MS)` 이상으로** 두어 얼굴 픽셀을 확보합니다. `자동`은 전신이
  잡혀 얼굴이 작아집니다.
- 얼굴을 반드시 유지해야 하면 얼굴 전용 수단(얼굴 디테일러 등)을 함께 씁니다.
  구도를 크게 바꾸는 컷은 참조 얼굴 픽셀이 남지 않으므로, 이 노드만으로는
  얼굴이 그대로 유지되지 않습니다.

### 5-3. 의상 교체

**앞 번호가 의상 소스, 뒤 번호가 입는 사람**입니다.

```
2 의상, 1 교체
2번 의장을 1번 인물에게 입혀
이미지 2 의상을 이미지 1에 적용
```

`의상`·`옷`·`옷차림`·`의장`·`생활복`·`드레스`·`원피스` 같은 말을 알아듣습니다.
`2번 드레스를 입은 여성`처럼 **입고 있는 사람**을 가리키는 표현은 의상 소스가
아니라 인물로 봅니다.

**상태를 말하는 것과 바꾸라는 것은 다릅니다.**

| 적은 문장 | 해석 |
|---|---|
| `1번 인물이 신발을 신고 있다` | 상태 묘사 → 참조의 신발을 그대로 유지 |
| `검은 구두를 신는다` | 교체 지시 → 그 신발로 바꿈 |
| `흰색 단화로 갈아입혀` | 교체 지시 (색·품목이 있으면 교체) |
| `2번 옷으로 갈아입혀` | 교체 지시 (번호를 함께 적으면 교체) |

즉 **하고 있는 모습**을 적으면 참조를 지키고, **구체적인 품목·색·재질**을 적거나
`입혀라`·`신어라`처럼 시키면 그 옷으로 바꿉니다.

### 5-4. 두 사람

```
1번 이미지 여성, 2번 이미지 남성, 3번 여성 포즈, 4번 남성 포즈
```

두 사람을 지정하면 "한 명만" 억제가 풀리고, 각자의 신원을 따로 유지합니다.
두 신체가 하나로 합쳐지거나 팔다리가 뒤섞이는 것도 막습니다.

### 5-5. topic을 비웠을 때 — 참조를 자동으로 분석합니다

이미지만 연결하고 topic을 비우면 노드가 **각 이미지를 픽셀로 분석해 역할을 정합니다.**

> **`topic` 은 직접 적든 텍스트 박스를 연결하든 같은 글로 취급됩니다.** 픽셀 분석은
> 항상 돌지만, `topic` 이 슬롯을 지목하면 그 판정이 우선합니다(아래 마지막 항목).

- **사람이 있는 칸을 찾아** 그중 첫 번째를 주 피사체(얼굴·체형·의상 기준)로 씁니다.
  다른 사람이 있으면 보조 인물로 따로 유지합니다.
- 사람이 없는 칸은 보조 참조(배경·사물·스타일)로 둡니다. 얼굴·의상을 복사하지 않습니다.
- 그래서 **1번에 옷이나 사물을 넣어도 됩니다.** 사람이 2번에 있으면 2번이 주 피사체가 됩니다.
- 분석 결과는 콘솔에 남습니다: `참조 자동 분류 — 인물 슬롯 2`.
- topic에 `2번은 포즈만`처럼 **번호로 역할을 적으면 그 판정이 항상 우선**합니다.

**단색 배경 위의 물건은 "아이템"으로 봅니다** (옷 사진·제품 사진·스튜디오 가구).
옷인지 사물인지는 픽셀만으로 가를 수 없어서, 노드는 "아이템"까지만 판단하고
입힐지 놓을지는 모델이 상황에 맞게 정하도록 맡깁니다.

- 옷 사진이면 그 옷을 다른 참조의 인물에게 입히고, 사물·제품이면 원래 형태와
  재질·색을 유지한 채 장면에 놓습니다.
- 방 사진처럼 여러 물건이 있는 이미지는 아이템으로 보지 않습니다. 단색 배경 위
  물건 하나만 아이템입니다.
- 사람을 찾는 분석이 어려운 환경에서는 1번 이미지를 주 피사체로 봅니다.

**AI 판단 (llm) 을 쓰면 역할을 더 정확히 나눕니다.** LLM이 첨부한 이미지를 직접
보고 각 칸의 역할을 정하고, 그 판단이 픽셀 판정보다 우선합니다. 역할은 사람·의상·
사물·배경·스타일·포즈 여섯 가지이며, 실제로 연결되지 않은 칸은 무시합니다.

> 자동 분석에는 `mediapipe` 와 포즈 모델(`.task`)이 필요합니다. 둘 중 하나라도
> 없으면 분석만 꺼지고 나머지는 그대로 동작합니다 (1절 참고).

캐릭터 시트는 topic이 비어 있어도 픽셀로 찾아냅니다.

### 5-6. 캐릭터 시트 (턴어라운드)

정면·후면·측면처럼 **같은 사람이 여러 각도로 반복된 한 장**을 캐릭터 시트라고
합니다. 이런 이미지를 연결하면 노드가 자동으로 알아보고, "모든 뷰는 같은 한 사람"
이라는 지시와 함께 시트 모양이 결과에 그려지지 않게 처리합니다.

**쓰는 법**

1. 시트 이미지를 `image_1`~`image_10` 중 아무 칸에 연결합니다. 번호는 상관없습니다.
2. topic은 **비워 두는 편이 안전합니다.** 장면을 적으면 "여러 각도를 보여 달라"로
   읽힐 여지가 있습니다.
3. 다른 참조(포즈·배경·소품)를 함께 연결해도 됩니다.

**두 종류를 구분해야 합니다**

| 종류 | topic 표현 | 해석 |
|---|---|---|
| 1인 시트 (기본) | `캐릭터 시트`, `턴어라운드`, `삼면도`, `다각도` | 반복된 뷰가 모두 같은 사람 |
| 다인물 시트 | `여러 캐릭터`, `여러 명의 캐릭터`, `다른 캐릭터`, `라인업`, `다캐릭터`, `오디션 시트`, `multiple characters`, `cast sheet` | 패널마다 다른 사람 |

여러 명이 한 장에 있는데 1인 시트로 처리되면 "모두 같은 사람"이 되어 결과가
이상해집니다. 이때는 `여러 캐릭터` 같은 표현을 topic에 적어 주세요.

**자동 판별이 안 될 때**는 배치가 불규칙한 경우입니다. topic에 `캐릭터 시트`를
직접 적으면 됩니다. 3뷰(삼면도)처럼 뷰가 적은 시트도 topic에 시트라고 적으면
시트로 처리합니다.

**AI 판단 (llm)** 을 쓰면 시트가 1인인지 다인물인지도 구분합니다. 같은 사람이
여러 각도로 나온 것이면 "전부 같은 한 사람", 다른 캐릭터가 나열된 것이면
"패널마다 다른 인물"로 지시가 갈립니다. topic에 `여러 캐릭터`처럼 적으면 사용자
판정이 항상 우선합니다.

> 시트는 **신원을 파악하는 데만** 쓰고, 그림을 그리는 쪽으로는 넘기지 않습니다.
> 그래서 시트를 연결해도 결과가 여러 칸짜리 시트로 나오지 않고,
> `image_out`·`reference_latent_out` 에서도 빠집니다.

### 5-7. 자동으로 붙는 안전장치

따로 켜고 끄는 설정은 없습니다. 상황을 보고 필요한 문구만 자동으로 붙습니다.

- **인물 장면**: 손가락·발가락 개수, 팔다리 분리, 피부 질감, 얼굴 구조 유지.
- **사람이 없는 장면**: 풍경·사물처럼 사람도 동물도 아니고 참조에서도 사람이
  검출되지 않으면, 손가락·피부 같은 사람 전용 문구뿐 아니라 **얼굴 구조·체형
  유지 문구도 붙이지 않습니다.** 사람 참조가 한 장이라도 있으면 그대로 유지되므로,
  사람이 없는 참조(풍경·제품·차량)에서 없던 사람이 생기지 않습니다(동물 장면도
  사람 전용 문구는 붙지 않습니다).
- **포즈 지시**: 자세를 바꾸라고 하면 모델이 얼굴까지 새로 그립니다. 다른
  사람이 되지 않도록 얼굴 고정 문구를 negative에 넣습니다.
- **정면 응시**: `정면을 바라본다`, `facing forward` 같은 지시가 있으면 고개가
  돌아가지 않게 잡습니다.
- **참조를 쓸 때**: 부위 경계(다리·팔·어깨가 뭉개지지 않게), 의상이 피부에
  융합되지 않게, 참조끼리 얼굴이 섞이지 않게.
- **의상 색**: 토픽에 색을 적었으면 그 색으로 고정하고, 다른 색으로 바뀌는 것을
  negative로 막습니다.
- **신발**: 참조 인물의 신발을 그대로 유지합니다. 색·실루엣·끈·굽 높이·재질이
  바뀌거나 다른 신발로 갈아타는 것을 막습니다. 신발을 바꾸라고 지시하면 그
  지시가 우선합니다.
- **사물·가구 참조**: 형태·재질·색·비율을 원본 그대로. "비슷하지만 다른 가구"로
  바뀌는 것도 막습니다.
- **접촉·동작 표현**: `밀어붙였다`, `안고 있다`, `던진다`, `달리고 있다` 같은
  말이 있으면 접지·무게·중간 자세까지 지시합니다. 다만 **동물 주제에는 사람
  관절·보행 문장을 붙이지 않습니다**(`달리는 말`에 사람 다리 문장이 붙지 않게).
  사람이 함께 있는 장면은 그대로입니다.
- **제거 장면**: 벗거나 떼어낸 사물의 반쪽·조각이 남지 않게 막습니다.
- **가림·노출**: **사용자가 직접 지시할 때만** 반영합니다. `가려줘`라고 적으면 가림
  문구를 positive에 넣고, `드러내줘`라고 적으면 넣지 않습니다. 아무 말도 안 하면
  위험한 조합이라도 자동으로 개입하지 않습니다(모델이 스스로 결정).
- **참조가 2장 이상**: 참조 사이의 거리와 화면 아래 여백을 픽셀로 재서
  "붙어 있는지 떨어져 있는지"를 유지합니다. 조명 방향이 서로 반대면 콘솔에
  경고가 뜹니다.
- **배경 참조**: `4번: 배경` 처럼 배경으로 선언한 참조는 바닥 재질·벽·러그 같은
  **표면**을 그대로 유지합니다(실내·야외 모두). 조명은 **조명 칸이 `자동`일 때**
  참조 배경의 광원(방향·그림자·색온도)을 기준으로 삼고, 조명이나 그레이드를
  **직접 고르면 고른 값이 우선**합니다. 자세한 규칙은 **5-8** 에 정리했습니다.

### 5-8. 참조 배경을 쓸 때 — 무엇이 참조를 따르고, 무엇이 내 설정을 따르는가

`4번: 배경` 처럼 참조 한 장을 **배경으로 선언**하면 그 참조가 결과의 배경이
됩니다. 이때 무엇이 참조를 따르고 무엇이 카메라 설정을 따르는지는 아래와
같습니다.

| 대상 | 누가 이기나 |
|---|---|
| 바닥 재질·바닥 무늬·벽·천장·창·커튼·러그 | **항상 참조를 따릅니다.** 조명이 자동이든 직접 고른 값이든 상관없습니다 |
| 조명 (빛의 방향·그림자·색온도) — 조명 칸이 `자동` | **참조 배경 광원이 기준**입니다. 카메라가 자동으로 채운 조명(구도 규칙·이미지 힌트·기본 창가빛)은 피사체에만 적용됩니다 |
| 조명·그레이드 — `프리셋` 또는 드롭다운으로 **직접 고름** | **고른 값이 1순위**입니다. 참조가 그 선택을 덮지 않습니다 |
| 장면 분위기와 피사체 | 프롬프트(`topic`) 내용에 따라 변형됩니다 |

**왜 이렇게 나뉘나**: 배경으로 선언한 것 자체가 "이 배경을 쓰겠다" 는 사용자
지시라서 **표면**은 참조가 우선입니다. 반대로 조명·그레이드를 직접 고른 것은
"이 분위기로 찍겠다" 는 지시라서 참조가 덮으면 안 됩니다. 그래서 **직접 고르면
내 설정, 자동이면 참조**입니다.

**조정은 콘솔에 알립니다.** 참조 광원을 기준으로 삼았는지, 내가 고른 조명을
그대로 썼는지 실행 로그에 한 줄 남습니다 — 말없이 바뀌지 않습니다.

> 요약: **표면은 참조, 조명은 자동이면 참조 / 직접 고르면 내 설정.**

## 6. 한글 → 영어 번역 (선택)

`규칙 (auto)` 모드에서 topic이나 `prompt_in`이 한글이면, 번역 모델이 있으면
영문으로 바꿔서 내보냅니다. `AI 판단 (llm)` 모드는 LLM이 직접 영문 장면을
만들므로 번역을 쓰지 않습니다.

- **모델 위치**: `ComfyUI/models/translation/tc-big-ko-en` 폴더에 넣어 두면 됩니다.
- **노드에 함께 들어 있지 않습니다.** 약 420MB를 한 번만 받아 두면 됩니다.
- **없으면 그냥 한글이 나갑니다.** 번역은 조용히 꺼지고 노드는 정상 동작합니다.
- 영어만 쓰면 모델을 아예 불러오지 않으므로 영향이 없습니다.
- 같은 문장을 다시 쓰면 번역 결과를 재사용합니다(두 번째부터 빠릅니다).

## 7. LLM 설정 (`AI 판단 (llm)`을 쓸 때만)

| provider | 기본 모델 | 키 |
|---|---|---|
| OpenAI | `gpt-4o-mini` | `api_key` 또는 `OPENAI_API_KEY` |
| Anthropic | `claude-3-5-haiku-latest` | `api_key` 또는 `ANTHROPIC_API_KEY` |
| Gemini (무료 티어) | `gemini-1.5-flash` | `api_key` 또는 `GEMINI_API_KEY` |
| OpenRouter (무료 모델 있음) | `google/gemini-flash-1.5` | `api_key` 또는 `OPENROUTER_API_KEY` |
| Groq (무료 티어) | `llama-3.2-90b-vision-preview` | `api_key` 또는 `GROQ_API_KEY` |
| DeepSeek (저가) | `deepseek-chat` | `api_key` 또는 `DEEPSEEK_API_KEY` |
| Mistral (무료 티어) | `pixtral-12b-2409` | `api_key` 또는 `MISTRAL_API_KEY` |
| Ollama (로컬) | 설치한 모델 이름 | 키 없음. `ollama serve`만 켜 두면 됨 |
| LM Studio (로컬) | 로드한 모델 이름 | 키 없음. Local Server를 켜면 됨 |
| Custom (OpenAI 호환) | 직접 입력 | 선택. 키 없는 게이트웨이도 가능 |

- **이미지 판단을 하려면 비전을 지원하는 모델**이어야 합니다. 텍스트 전용 모델을
  고르면 판단이 실패하고 규칙으로 돌아갈 수 있습니다.
- Gemini는 [Google AI Studio](https://aistudio.google.com/)에서 무료 키를 받을 수 있습니다.
- OpenRouter는 `model` 칸에 `:free`로 끝나는 이름을 넣으면 무료로 쓸 수 있습니다.
- `Custom`은 `custom_base_url`에 주소(예: `https://api.example.com/v1`)를 넣고
  `model`에 그 서버의 모델 이름을 적습니다.
- 로컬 LLM은 응답이 오래 걸릴 수 있어 기다리는 시간이 길게 잡혀 있습니다.

### 키를 안전하게 보관하는 법 (권장)

ComfyUI 맨 위 폴더에 `.env` 파일을 만들고 적어 두면 `api_key` 칸을 비워도 됩니다.

```
OPENAI_API_KEY=sk-...
GEMINI_API_KEY=...
```

- 우선순위: **칸에 입력 > `.env` 파일 > 운영체제 환경변수**
- `api_key` 칸에 키를 넣고 확인을 누르면 `.env`에 저장되고 칸은 비워집니다.
- 저장·공유되는 워크플로 파일과 생성된 사진(PNG 메타데이터)에는 키가 남지 않습니다.
- **예외 하나**: `Export (API)`로 내보낼 때, 그리고 `Custom`·`Ollama`·`LM Studio`는
  저장할 `.env` 자리가 없어 칸에 남습니다. 이 경우에만 내보내기 전에 칸을 비우세요.
  노드를 우클릭하면 **`api_key 지우기 (공유용)`** 메뉴가 있습니다.

## 8. 자주 겪는 문제

| 증상 | 해결 |
|---|---|
| 노드가 안 보임 | 폴더 위치와 `__init__.py`를 확인하고 ComfyUI를 재시작 |
| `prompt_in`에 선이 안 붙음 | 위젯 우클릭 → *Convert widget to input* (또는 선을 위로 끌어다 놓기) |
| `AI 판단 (llm)`인데 결과가 평범함 | 콘솔의 LLM 실패 메시지 확인 (키·모델명·서버 실행 여부). 실패하면 규칙으로 돌아갑니다 |
| 한글이 그대로 나감 | `AI 판단 (llm)`으로 바꾸거나 번역 모델을 설치 |
| 이미지 안의 한글이 깨짐 | 대부분의 이미지 모델은 한글을 못 그립니다. 글자를 잘 그리는 모델을 고르거나, 글자는 이미지 편집기로 따로 합성하세요 |
| 결과에 사람이 두 명 나옴 | 1인 시트인데 다인물로 처리된 경우. topic에 `캐릭터 시트`를 명시 |
| 결과가 여러 칸 시트처럼 나옴 | 시트가 아닌 이미지가 시트로 잡힌 경우. topic에 `캐릭터 시트`를 빼고 장면을 설명 |
| `image_out`·`reference_latent_out`이 비어 있음 | 시트 이미지만 연결된 경우입니다. 시트는 모든 출력에서 빠지므로, 시트 외에 참조를 하나 더 연결하세요 |
| 참조의 옷이 그대로 복사됨 | 그 슬롯의 역할을 topic에 적으세요(`2번은 배경만`) |
| 인물이 뭉개짐 | denoise를 낮추고(0.6~0.8) 해상도를 올리세요. `pf_denoise`에 값을 적으면 경고해 줍니다 |
| 팔 하나가 사라짐 | 참조의 팔이 새 자세에 안 맞을 때 생깁니다. 토픽에 팔 위치를 적으세요(`양손을 무릎에 올려놓고`). 4-7 참고 |
| 옷이 다른 옷으로 바뀜(긴 바지→반바지) | 옷 이름을 토픽에 적으세요. 적지 않으면 참조 이미지만 기준이 됩니다. 4-7 참고 |
| 얼굴이 참조와 달라짐 | 포즈를 지시했는지 확인하세요. 토픽에서 포즈 문장을 빼고 샷을 `중경` 이상으로 두세요. 그래도 부족하면 얼굴 전용 수단을 함께 쓰세요 |
| 신발 색·스타일이 바뀜 | 참조 신발을 유지하는 가드가 자동으로 붙습니다. 그래도 바뀌면 토픽에 원하는 색·스타일을 직접 적으세요 |
| `pose_image`를 넣었는데 자세가 안 바뀜 | 손·얼굴까지 그린 맵은 자세를 잘못 읽을 수 있습니다. 몸만 그린 맵을 연결하세요 |
| 참조 이미지를 바꿨는데 결과가 그대로 | 캐시가 남은 경우입니다. ComfyUI를 재시작하세요 |
| 결과물이 내가 고른 비율과 다르게 나옴 | `latent_image`(Empty Latent 등)를 연결했는지 확인하세요. 연결하면 5번 출력이 그 크기 그대로 나갑니다. 연결하지 않으면 참조 이미지 비율을 따릅니다(4-8) |
| 결과물이 커지지 않고 1MP(예: 752x1360)에 머묾 | `latent_image`(해상도 노드)가 연결되지 않은 경우입니다. 해상도 노드를 연결하면 5번 출력이 그 크기 그대로 나가고 참조도 그 픽셀 수를 따릅니다(4-8) |
| 같은 시드인데 결과가 달라짐 | 시작 latent 의 크기가 바뀌면(`denoise=1.0`) 시드가 달라진 것과 같습니다. 실행 사이에 해상도 노드의 비율·메가픽셀을 바꾸지 마세요 |
| 사진의 모양과 결과 구도가 따로 놂 | 참조 사진의 종횡비를 그대로 살리는 것이 정상 동작입니다(여백·크롭·늘리기를 하지 않습니다). 모양을 맞추려면 사진을 미리 그 모양으로 준비하세요(4-8) |
| 피부가 플라스틱처럼 보임 | 앞단 프롬프트의 `flawless`·`smooth`를 빼고, 그레이드를 `시네마틱 필름`·`35mm 필름`으로 |
| 콘솔의 이모지가 `?`로 보임 | Windows 콘솔 표시 문제입니다. 기능과 무관합니다 |
| 공유했더니 API 키가 딸려감 | `Export (API)` 파일인지 확인. 위 7절의 예외 항목 참고 |

## 9. 스토리보드처럼 이어서 만들기

한 장을 뽑고 그 결과를 다시 참조로 쓰면 **사본의 사본**이 되어 화질과 인물이
조금씩 변합니다. 이어지는 컷을 만들 때는 아래를 지키세요.

1. **참조는 항상 최초 원본**을 씁니다. 직전 결과물을 다시 넣지 않습니다.
2. **PNG 저장본**을 씁니다. 미리보기를 끌어다 쓰거나 JPG를 쓰면 그 자체로 손실입니다.
3. **프리셋과 카메라 값을 전 컷에 고정**합니다. `자동`은 입력 이미지에 따라
   조명·색보정을 바꾸므로 컷마다 룩이 달라질 수 있습니다.
4. **같은 사람은 같은 번호**에 연결합니다. 1번=주인공, 2번=조연처럼 정했으면
   전 컷에서 바꾸지 마세요.
5. **해상도를 통일**합니다. 기준 크기가 바뀌면 참조의 세부가 달라집니다.
6. **2차 패스의 denoise를 낮게** 잡습니다.
7. **컷마다 바뀌는 것은 장면 설명뿐**으로 둡니다.
