# 🛡️ (GoRi) Consistency Keeper

> 🌐 [English version](README.en.md)
>
> ☕ 도움이 됐다면 커피 한 잔: [PayPal로 후원하기](https://paypal.me/GoRi57788)

샘플러가 뽑은 latent를 원본·카메라 기준 latent 쪽으로 당겨
신원·구도 틀어짐을 줄이는 2차 패스 노드. **다시 그리지 않는다**
(재인코딩·재샘플링 없음).

## 배선

```text
LoadImage → VAE Encode ── original_latent ──→ ┐
(GoRi) Camera Director Skills ── reference_latent_out ── camera_latent ──→ (GoRi) Consistency Keeper ── latent_out ──→ VAE Decode → SaveImage
KSampler ── LATENT ── sampled_latent ──→ ┘
같은 VAE ── vae ──→ ┘ (인체 마스크용, 선택. 미연결이면 전역 당김)
```

`original_image` (IMAGE, 선택)를 연결하면 원본 기준을 Latent 대신
이미지로 직접 인코딩해 세운다. Qwen Edit 의 latent 출력은 전부 0 인
빈 캔버스라 Latent 기준이 무의미할 때 이쪽이 정확하다(우선 적용).

## 위젯

| 위젯 | 기본값 | 설명 |
|---|---|---|
| `strength_sampler` | 1.0 | 전체 보정량 마스터 게인. 1.0=기존 동작 그대로, 0.0=통과(출력=입력), 0.5=절반만 반영. 음수는 보정을 뒤집는다 |
| `strength_camera` | 0.2 | 연출 방향 당김 (카메라 기준, -1.0~1.0) |
| `strength_original` | 0.2 | 원본 신원 당김 (-1.0~1.0) |
| `trust_gate` | False | 판정 게이트. 켜면 원본의 포즈·손 판정으로 **부위별 복원(디테일 상향)**을 원본에서 당겨와도 되는 부위만 적용한다(손상된 부위는 상향 차단, 판정 불가 시 기존 동작+사유 로그). 기본 당김 강도 자체는 게이트와 무관하게 그대로 적용된다. 꺼면 기존 동작 |
| `repair_enable` | False | 판정 주도 교정 당김(opt-in). 켜면 물리 판정이 파손으로 본 부위를 골격 교정으로 당겨온다(기본 경로는 이 블록이 없는 것과 같다) |

음수는 **안티-레퍼런스** (닮음 밀어내기). 틀어짐이 크면 노드가 스스로
당김을 감쇠시킨다 ("융합하되 변형 없이" — 콘솔에 감쇠 알림).
조명 흐름이 다르면(Retinex 근사: 저주파 명암 비교) 추가로 감쇠된다.

## 인체 마스크 가중 당김 (선택)

`vae`를 연결하면 인체 영역만 골라 당긴다 (MediaPipe 포즈 분할 마스크 —
미설치면 안내 한 번 후 전역 당김으로 동작, 별도 설정 없음). 배경은 그대로 두고
신체 전체를 커버한다. 손가락 개수 자체는 고치지 못한다 (디테일러 영역).

0이면 해당 기준 생략. 기준 latent 미연결·크기 불일치(배치·채널)도 건너뛰고
콘솔에 알린다. 공간 크기가 다르면 bicubic 리사이즈로 맞춘다.

## 세팅 가이드

> ### ⭐ 권장값: `camera` 0.2 / `original` 0.2 (물리 상한)
>
> 이 노드는 참조별 당김에 **실측 물리 상한 0.20** 을 둡니다 — 0.20 을 넘기면
> 결과가 원본보다 뭉개진다는 대응 지점 실측(2026-09-28)이 근거입니다.
> 0.20 을 넘는 위젯 값은 **자동 감쇠가 발동하지 않을 때 0.20 과 동일하게
> 동작**하며, 상한에 걸렸을 때 매 실행 "당김이 물리 상한을 넘었습니다"
> 경고를 남깁니다. 참고로 구도 불일치 자동 감쇠(위젯 절)가 먼저 적용되면
> 그 값이 0.20 이하일 때는 상한 경고 없이 통과합니다. 과거 권장이던 0.33 도
> 실제로는 0.20 으로 잘렸습니다. 시작값은 0.2 / 0.2 로 하고 아래 표로만
> 내립니다 — 올리는 방향은 0.20 에서 막힙니다.

| 값 | 언제 쓰나 |
|---|---|
| **0.2 / 0.2** | **시작값 — 상한. 0.2 를 넘는 값은 전부 여기와 동일** |
| 0.15~0.2 | 눌어붙은 느낌·밋밋함 (과다 당김) |
| 0 또는 미연결 | 기준 하나만 쓸 때 |

| 증상 | 조절 |
|---|---|
| 얼굴이 원본과 다름 | `original` 을 상한(0.2)까지. 그래도 부족하면 **부위별 자동 복원**(아래 절)이 담당합니다 |
| 구도·조명이 샘플러 멋대로 | `camera` 를 상한(0.2)까지 |
| 눌어붙은 느낌·밋밋함 | 둘 다 0.15~0.2로 내림 (과다 당김) |
| 두 사람이 하나로 뭉침 | 둘 다 0.15~0.2로 내림 |
| 기준 하나만 쓸 때 | 안 쓰는 쪽 0 또는 미연결 |

한 번에 하나씩 0.05~0.1 단위로 조절 (둘 다 크게 올리면 과해짐). 연산이 가벼워
VRAM·속도 부담은 없음.

## 부위별 디테일 손실 자동 복원 (setting 불필요)

샘플러 결과가 원본보다 **뭉개진 부위**(손·다리·얼굴)를 픽셀로 찾아내어,
그 부위만 `original` 강도를 자동으로 올립니다. 콘솔에 예:

```
[GoRi Consistency Keeper] 부위별 복원 강도 상향 (hand_left(89%), leg_left(72%))
— 원본이 살아있는데 결과가 뭉개진 부위를 원본으로 당겨옵니다
```

Camera Director가 프롬프트에 넣는 "손가락 5개" 같은 개수 지시는 diffusion이
강제하지 못합니다. 이 노드는 그 지시를 **실패했을 때를 픽셀로 잡아내는 역할**입니다.

한계: 원본에 디테일이 아예 없으면 건드리지 않습니다(원본을 신뢰할 수 없으면
복원도 틀립니다). MediaPipe가 있어야 landmark를 잡으므로, 미설치 시 안내
한 번 후 기존 동작으로 돌아갑니다.

## 캐릭터 시트 참조 자동 판별 (setting 불필요)

`original` 참조가 **캐릭터 시트**(정면·후면·상부얼굴 등 여러 뷰를 일자로
나열)인지 픽셀로 확인하고, 샘플 결과와 가장 잘 맞는 **뷰 하나**를 고릅니다.
콘솔 예:

```
[GoRi Consistency Keeper] original 참조에서 6개 패널 검출 — 캐릭터 시트 형태로 보입니다
[GoRi Consistency Keeper]   가장 일치하는 뷰: 3번 패널 (유사도 0.81)
[GoRi Consistency Keeper]   프레이밍 유사도 0.72 — 픽셀이 대응하므로 이 뷰를 신원 소스로 쓸 수 있습니다
```

- Camera Director는 시트를 한 덩어리로 보기 때문에 뷰별 신원 차이가
  프롬프트로는 제어되지 않습니다. 이 판별은 그 부분만 픽셀로 처리합니다.
- 시트로 오판하면 뷰들이 여러 사람 신원으로 평균나 **오히려 신원 일관성이
  망가지므로**, 패널이 4개 이상이면서 패널 간격이 고른 경우에만
  시트로 인정합니다(불규칙한 사진은 시트로 보지 않습니다).
- 시트로 판정되면 결과와 가장 잘 맞는 패널을 기준 원본으로 쓰고
  (2단계 A), 프레이밍이 게이트를 통과하지 못하면 `strength_original` 을
  절반으로 낮춥니다 (2단계 B).
- `mediapipe`가 없으면 프레이밍 판정이 실패한 것으로 처리합니다 — 패널을
  신원 소스로 쓰지 않고(B) `strength_original` 을 절반으로 낮춥니다.

## 운영체제 (Windows / macOS / Linux)

세 OS 모두 지원하며 CI(ubuntu/windows/macos × Python 3.10/3.12)에서 검증됩니다.
`torch`와 `numpy`는 ComfyUI 환경에 이미 있습니다. `mediapipe`는 선택 의존이라
없으면 해당 기능이 꺼지며, 그 이유를 콘솔에 한 번 알립니다.

이 노드는 latent 텐서와 포즈·손 검지용 `.task` 모델 파일 **읽기**만 합니다
— 파일을 쓰지는 않으므로 OS별 경로 차이의 영향이 없습니다.

- **macOS Apple Silicon(M1/M2/M3)**: mediapipe 휠이 없어 인체 마스크가
  자동으로 꺼집니다. 부위별 에지 대조·조명 흐름·캐릭터 시트 패널 검출은
  torch/numpy만 써서 그대로 동작합니다.
- GPU는 CUDA·MPS(Mac)·CPU 모두에서 예외 없이 동작합니다.

## 포즈·손 검지 모델 (mediapipe)

`mediapipe`는 선택 의존으로, 노드 폴더에 함께 배포되는 `.task` 모델 파일
세 개(`pose_landmarker_lite.task`, `hand_landmarker.task`,
`face_landmarker.task`)를 사용합니다. 기본값으로 그 파일들을 쓰며,
`GORI_POSE_MODEL` · `GORI_HAND_MODEL` · `GORI_FACE_MODEL`
환경변수로 다른 모델 파일 경로를 지정할 수 있습니다.

개발용 진단 옵션 하나가 더 있습니다. `GORI_PROBE_PHYSICS=1` 환경변수를
켜면 당김 방향의 물리성을 측정하는 추가 로그가 나옵니다 — 매 실행마다
디코드를 3회 더 하므로(비용 3배) 평소에는 끄는 것이 좋습니다.

모델 파일이나 mediapipe 가 없으면 인체 마스크와 포즈·손 기능은 꺼진 채로
전역 당김만 계속 동작합니다 — 이때 이유를 콘솔에 **한 번만** 알립니다
(매 실행마다 반복하지 않습니다).


## 배치(Batch) 입력

`sampled_latent`가 배치(2장 이상)면 **전역 당김만** 적용됩니다.
인체 마스크·부위별 복원·캐릭터 시트 분석은 단일 이미지 전용이라 자동으로
꺼지고, 콘솔에 그 사실이 표시됩니다. 강도 값은 그대로 적용됩니다.

배치로 돌리려면 이미지를 나눠 한 장씩 실행하거나, 강도를 낮춰 전역 당김만
사용하십시오.

## 겹쳐보임(고스트) 대처

얼굴·몸이 이중으로 겹쳐 보이면 기준 latent와 결과물 구도가 다른 것이다.
latent 블렌드는 같은 구도에서만 성립한다:

1. 기준 이미지를 결과물과 같은 구도·포즈로 맞춘다 (가장 확실)
2. 강도를 0.1~0.15까지 낮춘다
3. 콘솔에 "구도가 많이 다름" 경고가 뜨면 위 둘 중 하나 실행

## 문제 해결

**매 실행 `인체 마스크 없음 — 전역 당김으로 진행합니다` 가 뜰 때:**
마스크가 만들어지지 않은 것이다. 이 줄은 매 실행 반복되지만, **근본 원인은
프로세스당 한 번만** 별도 줄로 남는다(반복 로그가 원인 줄을 가리지 않는다).
콘솔을 위로 올려 아래 중 해당하는 줄을 찾는다.

| 근본 원인 줄 (한 번만 나옴) | 의미 |
|---|---|
| `인체 마스크·부위별 강도·프레이밍 판정이 꺼져 있다 ...` | mediapipe 미설치 또는 `.task` 모델 파일을 못 읽음 — 위 "포즈·손 검지 모델" 절의 확인 항목과 `GORI_POSE_MODEL` 경로를 본다 |
| `⚠ person mask failed in _person_mask_from_rgb` | 마스크 기하 계산에서 예외 — 뒤에 붙은 예외 이름·메시지 확인 |
| `⚠ pose inference failed in ...` | 포즈 추론 실행에서 예외 — 뒤에 붙은 예외 이름·메시지 확인 |
| `pose input 변환 실패 ...` | latent→검지 입력 변환에서 예외 — 뒤에 붙은 예외 확인 |

근본 원인 줄이 하나도 없다면 이미지에서 사람이 검출되지 않았거나(제품 사진·
원거리 인물 등) 마스크용 VAE 디코드가 실패한 것이다. 사람이 있는 이미지인데도
계속되면 `vae` 연결을 확인한다. 배치 입력이면 마스크 기능이 꺼지는 것이
정상이다(위 "배치(Batch) 입력" 절).
